# Context

Repo đã có nền Yule khá đầy đủ: 104 decor `yule_*` trong 11 collection, 12 crop mùa đông, skin/background cho các mini-game, lịch festival 15/11–05/01, theme `auto|on|off`, filter Yule và test asset. Người dùng muốn triển khai event chơi theo từng ngày từ 20/11 đến 25/12, mỗi ngày có 1 nhiệm vụ chính 5–10 phút và nhiệm vụ phụ; ngày bỏ lỡ được mở lại tự do; phần thưởng kết hợp gameplay; asset Yule mở bằng nhiệm vụ hoặc trả Sickle từ 20.000 trở lên; mỗi nhiệm vụ phụ tối đa 5.000 Sickle.

# Recommended approach

## 1. Model event state and schedule

- Add a versioned optional `yuleEvent` state to `GameState` with event key, progress, claimed main-day IDs, claimed side-task IDs keyed by event day, unlocked asset IDs, and last computed event day.
- Add typed definitions for the 36-day schedule (20/11–25/12), fixed main objectives, two optional side objectives/day, rewards, and asset unlocks.
- Keep event dates timezone-local and calculate day index from 20/11; allow any past active day to be claimed once while the event is active.
- Add migration/sanitization in `src/sim/simulationData.ts` so old saves remain valid and malformed rewards/IDs are clamped or discarded.

## 2. Implement engine APIs

- Create a focused module such as `src/sim/yuleEvent.ts` for pure schedule lookup, active-window checks, objective progress, reward validation, and asset unlock rules.
- Add `ParkSimulation` methods in `src/sim/simulation.ts` to get event status, claim a completed main task, claim a completed side task, and purchase an eligible locked Yule asset with Sickle.
- Reuse existing quest/objective snapshots and stats rather than adding duplicate counters where possible; add small explicit progress hooks only for actions not represented by existing objectives.
- Enforce economy rules centrally: side-task Sickle reward <= 5,000 per task, each task claims once, asset purchase minimum >= 20,000, no purchase of already unlocked assets, and no event claims outside 20/11–25/12 except a deliberate test override.
- Use existing catalog `yuleCollection`/`yule_*` items and ensure all 104 assets have deterministic prices and a valid unlock path. Make 25/12 award `yule_mini_hogwarts_castle` through the finale.

## 3. Add daily event UI

- Add a Yule event panel/card in the existing quest/HUD surface rather than a separate navigation system.
- Show current date, event day, main task, up to two side tasks, completion state, claim buttons, progress, and “open with Sickle” buttons for available Yule assets.
- Surface the Molly → Hedwig → Hogwarts progression and collection progress using existing Yule collection labels/filter.
- Ensure mobile layout and accessible labels; do not make neighbor tasks mandatory.

## 4. Tests and verification

- Add pure schedule tests for all 36 dates, pre-start/post-end behavior, missed-day reopening, and finale.
- Add simulation tests for save/load migration, one-time claims, side-task cap (<=5,000), duplicate claim prevention, Sickle purchase minimum/insufficient funds, asset unlock persistence, and final castle reward.
- Run targeted Vitest tests for simulation/Yule plus typecheck/build; inspect diff and report any pre-existing modified files not touched by this change.
